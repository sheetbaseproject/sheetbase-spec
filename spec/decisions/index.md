# Decision

* [ADR-001: Apache-2.0 for the whole org](adr-001-licence.md) - Every sheetbase repo is Apache-2.0 only, not MIT OR Apache-2.0, because Grist-derived material cannot be offered under MIT and a single licence keeps NOTICE handling simple.
* [ADR-002: Three repos, one cargo workspace](adr-002-repo-topology.md) - The org holds a spec repo, one cargo workspace with eight crates, and the Causl mirror; per-crate repos were rejected as coordination cost without a release-cadence benefit.
* [ADR-003: Causl behind a facade, from a public mirror, with a reference backend](adr-003-causl-dependency.md) - sheetbase-graph exposes a Graph trait; the default backend is causl-engine-core pulled by tag from a public MIT mirror, and a plain ReferenceGraph backend exists for differential tests and for builds without the mirror.
* [ADR-004: One Causl node per column, carrying a version token, never the data](adr-004-column-granularity.md) - Formula columns map to one derived node each and data columns to one input node each; node values are tiny version tokens, the rows live in sheetbase's column store, and row-level deltas are handled inside the compute. Per-cell nodes and per-column vector values both fail the 1M-cell arithmetic.
* [ADR-005: Grist relations are layered on Causl, not replaced by it](adr-005-relations-on-causl.md) - Causl owns the column-level graph (edges, order, glitch-freedom, cycles); sheetbase-core owns row-level relations (identity, reference, lookup, summary group) that run inside the compute to turn upstream dirty rows into the rows to recompute.
* [ADR-006: Column-level cycles collapse into a cycle group node evaluated cell by cell](adr-006-cycle-groups.md) - When Causl reports CycleClosed for a set of formula columns, sheetbase merges that strongly connected component into one derived node whose compute runs Grist's lazy per-cell evaluator with cell locks, so row-acyclic formulas keep working and true cycles become per-cell CircularRefError.
* [ADR-007: A Python-expression-subset formula language, no RustPython in v1](adr-007-formula-language.md) - Formulas are written in SFL, a Grist-syntax-compatible subset of Python expressions and small statement bodies, interpreted by a fuel-limited tree walker in sheetbase-formula; gridcraft's Excel engine supplies functions but not syntax; imported Python that the subset cannot compile is preserved and shown as
* [ADR-008: SQLite with the Grist schema, JSON action history, a marshal codec for compatibility](adr-008-storage.md) - Documents are SQLite files with Grist's exact user-table and _grist_* layout and value encoding so Grist can open what we save; sheetbase-only state lives in _sheetbase_* tables; action history is stored as JSON in our table and the Python-marshal history is read but never written.
* [ADR-009: Undo is inverse doc actions applied as a new commit, not Causl readAt](adr-009-undo-inverse-actions.md) - Every bundle records inverse doc actions as Grist does; undo applies them forward through the normal pipeline as a new Causl commit; Causl's read_at and retention ring are turned off for model nodes because the node values are version tokens.
* [ADR-010: egui 0.37 from upstream with eframe and wgpu, no fork](adr-010-egui-upstream.md) - The UI uses released egui/eframe/egui_extras/egui_kittest 0.37 from crates.io with the wgpu backend and AccessKit on; gridcraft's egui fork is not inherited, and its patches are tracked as upstream issues to watch.
* [ADR-011: The grid ports xldatagrid's pure decision layers onto egui, and merges them with Grist's view model](adr-011-grid-architecture.md) - Selection reducers, the keyboard decide() function, the pointer decision layer, the commit pipeline and the interaction reducer from xldatagrid are ported as pure Rust modules; DOM-specific pieces (ARIA attributes, CSS layers, portals, skins) are replaced by AccessKit, egui styles and egui popups; Grist's section/field model is the data these layers operate on.
* [ADR-012: Harvest gridcraft file by file under Apache-2.0 with notices; never its A1 model, chrome or forks](adr-012-gridcraft-harvest.md) - About 20k lines of gridcraft (number formats, functions, Value and coercion, theme tokens and contrast test, selection glide, font discovery, display cache, HTML clipboard) are copied verbatim with attribution; the formula parser skeleton, calc graph index, style model, grid geometry and paint pipeline, command and undo architecture, xlsx and csv readers are adapted; everything Excel-specific is rejected.
* [ADR-013: Access rules are parsed, stored and enforced in v1 for an explicit user context, with no identity provider](adr-013-acl-scope.md) - The full Grist rule grammar and default rule set are implemented in the engine pipeline (actions) and the view model (reads); the user comes from the process (desktop owner, CLI --as-user), not from authentication; user attribute tables and memos are in, share links and SchemaEdit nuances for editors are preserved but not exercised.
* [ADR-014: No server and no collaboration in v1; the headless surface is a local JSON-RPC over stdio](adr-014-no-server-v1.md) - v1 is a single-process desktop app plus a CLI. Multi-user sync is out; the CLI's `sb serve` exposes user actions over JSON-RPC on stdio so agents and tests can drive a document without a window.
* [ADR-015: One Value enum shared by formulas, store and UI, with Grist's type lattice](adr-015-value-model.md) - sheetbase-formula::Value is the single cell value type: Grist's wire codes map onto it losslessly, the store encodes it with Grist's rules, and the UI formats it; Int is i64 with Grist's 32-bit validity check, Numeric is f64, dates are f64 seconds like Grist.
* [ADR-016: Agents drive sheetbase through sb serve; the core never calls a network and ships no model](adr-016-agent-surface.md) - The agentic-AI use case is served by the headless JSON-RPC surface and a stable, documented action vocabulary; no LLM client, API key handling or assistant UI is in the core crates for v1, and a formula assistant, if built, is an external process talking to sb serve.
* [ADR-017: Named error enums per layer with a retryable flag and a defined UI behaviour per variant](adr-017-error-model.md) - Every crate exposes one error enum; variants carry structured fields, implement a `retryable()` method, and the UI behaviour for each variant is specified in the errors concept; panics are bugs and the app process guards them like gridcraft's Session does.
