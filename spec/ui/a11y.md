# The platform baseline

eframe's `accesskit` feature publishes an AccessKit tree to the platform (NSAccessibility,
UIA, AT-SPI). egui widgets set roles and labels; custom widgets set them through
`Response::widget_info` and `ui.ctx().accesskit_node_builder`. `egui_kittest` queries the same
tree and runs an accessibility check before every snapshot.[^egui-kittest]

# Commitments

Grid tree (one AccessKit node per *visible* cell, rebuilt per frame from the visible window;
off-screen cells are not in the tree, and `row_count`/`column_count` carry the totals):

| Element | Role | Properties |
|---|---|---|
| section | `Grid` | `label` = section title, `row_count` = rows + 1 header, `column_count`, `multiselectable`, `read_only` |
| header row | `Row` | `row_index` 0 |
| header cell | `ColumnHeader` | `label`, `sort_direction` (Ascending/Descending/Other), `column_index` |
| body row | `Row` | `row_index`, `selected` for row selection |
| cell | `Cell` | `row_index`, `column_index`, `value` = formatted text, `selected`, `read_only`, `invalid` with `error_message` for error cells, `description` = column description |
| gutter cell | `RowHeader` | `label` = row number |
| cursor cell | focused (`is_focused`) | keyboard focus follows the cursor; the grid container is the OS focus target and exposes the active cell via the focused node |
| in-cell editor | `TextInput` | egui's TextEdit node |
| new-row line | `Row` | `label` "add new row" |

Everything else uses egui's built-in roles (buttons, menus with `MenuItem`, dialogs with
`Dialog` and `modal`, trees with `Tree`/`TreeItem` for pages, tabs for the creator panel).

Announcer: a single hidden node with `live = Polite` whose `value` is set to the message
(`sheetbase-ui::a11y::Announcer::announce(msg, Priority)`), coalesced per frame, highest
priority wins. Announced: page change, section focus change (title), selection summary when a
range changes by keyboard ("3 rows, 2 columns selected"), F8 error navigation ("Error 2 of 5:
Amount, row 14. division by zero"), sort change, filter applied, undo/redo descriptions, import
done, save done. Not announced: every cursor move (the focused node carries it).

Focus order: page tree, section frames in layout order, within a section the header then the
grid, then the creator panel. `Tab` leaves the grid at its last cell (Grist and xldatagrid
agree). Dialogs trap `Tab` and return focus to the opener on close.

Motion: `Prefs.reduce_motion` (default from the OS where egui exposes it, else off) disables
the selection glide and the progress shimmer.

Contrast: see [theming](theming.md); `Prefs.high_contrast_gridlines` raises gridlines to 3:1.

Scaling: interface scale 75 to 200 percent applies to everything including the grid; text
size preference 12 to 20 pt.

# Gaps (honest)

- AccessKit on Linux (AT-SPI) is less complete than on macOS/Windows; screen reader testing is
  done on VoiceOver and NVDA, with Orca best-effort.
- egui has no `aria-activedescendant` equivalent; we expose the active cell as the focused node
  and rebuild the subtree per frame, which some screen readers read as focus churn when scrolling
  fast. Mitigation: only emit focus changes when the cursor actually moves.
- Rich text (Markdown widget) is exposed as plain text.
- No high-contrast *theme* in v1 beyond the gridline toggle; the token system allows one later.

# Tests

`kittest` queries by role and label for every widget in the catalogue; the accessibility check
runs before every snapshot; a `tests/a11y_grid.rs` asserts the row/column indices of the visible
tree against the view store for scroll positions at 0, mid and end.
